에이전트와 함께 테마 만들기

MarsDawn 미리보기 테마를 만드는 AI 에이전트를 위한 참고 자료입니다. 에이전트는 theme.json 하나를 쓰고 명령줄 도구 marsdawn으로 검사하고 렌더링한 뒤 링크를 건넵니다. 사람은 테마 만들기 페이지에서 눈으로 다듬어 제출합니다. 아래 필드 표는 kit의 소스 코드에서 직접 읽은 것이며, 검사가 둘이 같음을 보장합니다.

theme.json을 쓰고, 종료 코드가 0이 될 때까지 marsdawn theme validate theme.json --require-complete --json을 실행하고, marsdawn theme preview로 라이트와 다크를 렌더링한 뒤 사람에게 링크를 건네세요. 테마는 매개변수일 뿐이며 CSS를 담지 않습니다.

테마란 무엇인가

  • 라이트와 다크 각각의 색: 기본 팔레트와 선택 사항인 구문 색, 다이어그램 색. 모두 #RRGGBB 형식입니다.
  • 글꼴 디자인: sans, serif, rounded 중 하나.
  • 닫힌 스타일 옵션 집합: 고정된 범위의 숫자와 고정된 목록에서 고르는 값. 스타일 옵션의 색은 항상 accent 같은 팔레트 역할이며 색 값을 직접 쓰지 않습니다.
  • 표시 문자열: 이름과 요약, 그리고 선택 사항인 작성자와 라이선스.

아래 표에 없는 키는 오류이며, 같은 키를 두 번 쓰는 것도 오류입니다. 파일은 최대 16,384바이트입니다.

검사하고 렌더링하기

theme.json이 있는 폴더에서 실행하세요. marsdawn 도구가 필요합니다. 에이전트를 위한 marsdawn을 보세요.

marsdawn theme validate theme.json --require-complete --json
marsdawn theme css theme.json --json
marsdawn theme preview theme.json --appearance light -o light.png
marsdawn theme preview theme.json --appearance dark -o dark.png
  • 종료 코드: 0은 유효, 1은 규칙 ID와 함께 무효, 2는 파일 없음, 64는 사용법 오류입니다. preview에는 PNG가 이미 있을 때의 4(--force를 주거나 다른 이름을 고르세요)와 렌더링 실패의 5가 더해집니다.
  • --json을 주면 무효한 테마는 issues 아래에 문제를 나열하며, 각각 rule ID, path, message가 있습니다. 고친 뒤 다시 실행하세요.
  • --require-complete는 게시할 테마를 위한 검사입니다. 두 팔레트 모두에 syntax와 diagram 색도 요구합니다.
  • css는 미리보기가 쓰는 CSS를 출력하고, preview는 예시 문서를 PNG로 렌더링합니다. 둘 다 먼저 검증하므로 무효한 테마는 렌더링되지 않습니다.
  • 테마를 건네기 전에 라이트와 다크 PNG를 둘 다 확인하세요.

기본 제공 테마에서 시작하기

  • /assets/theme-sim/kit/themes/dawn.json: 기본값이며 아래 예시
  • /assets/theme-sim/kit/themes/classic.json: 더 차분한 문서 같은 팔레트
  • /assets/theme-sim/kit/themes/modern.json: 더 차갑고 현대적인 팔레트
  • /assets/theme-sim/kit/themes/vivid.json: 더 밝고 대비가 큰 팔레트

숫자는 가장 가까운 간격의 배수로 맞춰진 뒤 최소와 최대 사이에 있어야 합니다. 그렇지 않으면 규칙은 number.range입니다.

그 밖에 검사하는 것

  • 대비. background 위의 text처럼 미리보기가 그리는 모든 색 쌍은 텍스트는 4.5:1, 선과 그 밖의 비텍스트는 3:1을 만족해야 합니다. 지정한 시나리오는 일부 색을 4.5:1로 올립니다. 메시지에는 해당 쌍과 그 비율, 필요한 비율이 나옵니다.
  • 문자열. 이름, 요약, 작성자 이름이 비어 있거나 너무 길거나, 링크, 제어 문자, 보이지 않는 문자 또는 양방향 서식 문자를 포함하면 거부됩니다.
  • 규칙 ID. 모든 문제에는 contrast.pair, color.hex, number.range, id.pattern, schema.unknownKey, palette.incomplete 같은 ID가 붙습니다. ID와 path가 가리키는 대로 파일을 고치세요.

링크로 건네기

테마 만들기 페이지는 링크로 테마를 열어 사람이 눈으로 다듬을 수 있게 합니다. 링크는 그 페이지의 주소, #theme=, 그리고 패딩 없는 base64url로 인코딩한 파일 바이트로 이루어집니다. 파일은 최대 16,384바이트입니다. 이 한 줄이 macOS와 Linux의 zsh와 bash에서 링크를 만들어 줍니다.

printf 'https://marsdawn.southern-light.dev/ko/themes/new/#theme=%s\n' "$(base64 < theme.json | tr -d '\n=' | tr '+/' '-_')"

테마는 브라우저가 사이트로 보내지 않는 # 뒤에 담기며, 사이트는 이를 어디에도 보내지 않습니다. 다만 링크는 셸과 브라우저의 기록에 남고, 링크를 받은 사람은 누구나 테마를 읽을 수 있습니다.

제출하기

에이전트는 파일과 링크를 준비하고, 제출은 사람이 합니다. 두 방법 모두 Developer Certificate of Origin과 Apache-2.0 게시에 대한 확인이 필요하며, 이 확인은 사람이 직접 합니다. 에이전트가 상자에 체크하거나 대신 서명하지 않습니다.

  • 이슈. 사람이 링크를 열어 “테마 만들기” 페이지에서 Submit을 누르거나, 이슈 양식을 열어 JSON을 Theme에 붙여 넣습니다. 워크플로가 테마를 검사하고 답합니다.
  • 풀 리퀘스트. themes/<id>/theme.json만 바꾸고, author.github를 풀 리퀘스트 작성자의 로그인으로 설정하고, 모든 커밋을 git commit -s로 서명하세요. 규칙은 CONTRIBUTING.md에 있습니다.

제출된 테마의 작성자 이름, 이름, 요약, GitHub 로그인은 영구적으로 공개됩니다. author.name에는 그 사람이 공개해도 좋다고 한 이름을 넣으세요.
