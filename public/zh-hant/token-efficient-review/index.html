審閱不花 agent 的 token。

這個循環裡有兩件事分開來看，都很省：agent 呼叫工具拿回什麼，以及確認結果排版正確要花多少力氣。

工具呼叫回傳的是一個小小的 JSON 物件，不是排版後的頁面；排版後的頁面由人在 MarsDawn 裡閱讀——不會被讀回 agent 的 context。

工具呼叫本身很便宜

不管是從 CLI、skill，還是MCP 伺服器呼叫 marsdawn export，回傳的都是精簡的 JSON 物件：ok、output、pages、theme、paper 和 diagramErrors。完整 schema 在 export.v1.json。裡面沒有排版後的文件內容。一份 50 頁、有十幾張 Mermaid 圖表的 PDF，回傳的欄位和一則一頁的筆記一樣多。

審閱在另一邊進行

PDF 產生之後，人會打開它——在 MarsDawn 裡，或任何 PDF 檢視器——閱讀排版好的圖表、數學式和版面。agent 不需要把排版結果讀回自己的 context 才能確認它看起來對：審閱在另一個視窗、另一個畫面上進行，不會變成又一輪花 token 描述一張圖表長什麼樣子。

這樣省下什麼

  • 不用把排版後的 Markdown、一張截圖，或對截圖的描述貼回對話裡，只為了讓 agent 確認匯出成功。
  • agent 不需要重建 Mermaid 圖表或 KaTeX 公式排版後的樣子，直接讓人去看就好。
  • 不需要在第一次呼叫已經回報成功之後，再多一次呼叫去讀取 PDF 的內容。
