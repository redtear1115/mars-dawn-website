agent 寫出來，還是得由你理解。

AI agent 可以很快寫出一份計畫、一份規格或一堆筆記。它寫出來的東西，還是得由要照著做的人去理解——不能因為讀起來通順，就直接相信。

MarsDawn 就是為了這種閱讀而做的：排版後的頁面和原始碼並排，Mermaid 圖表和 KaTeX 數學式直接畫出來，而不是留著記號，讓文件的結構一眼就看得懂。

讀起來通順，不代表是對的

Simon Willison 在談 AI 輔助寫程式時，對那些還會被繼續維護、不是寫完就丟的程式碼這麼說：「the quality and understandability of the underlying code is crucial」（底層程式碼的品質和是否容易理解，至關重要，Vibe coding，2025）。文件也一樣：agent 寫出來讀起來很順的草稿，結構、數字或邏輯還是可能是錯的，而通順的文字並不會告訴你哪裡該多留意。

是推論，不是編譯

Thoughtworks 的 Birgitta Böckeler 講得很直接：「LLMs are NOT compilers, interpreters, transpilers or assemblers of natural language, they are inferrers」（LLM 不是自然語言的編譯器、直譯器、轉譯器或組譯器，它們是推論器，I still care about the code）。編譯器要嘛接受你的輸入，要嘛回報錯誤；agent 給你的東西即使能跑、讀起來也通順，也不保證是對的。還是得有人檢查。

MarsDawn 給讀的人什麼

  • 排版後的頁面和原始碼並排，兩邊一改就同步更新，讓文字裡的說法和它的結構同時在你眼前。
  • Mermaid 圖表畫出來：agent 用文字描述的流程圖，變成一個你真的能看懂的形狀。
  • KaTeX 數學式排版出來，不是留著一串反斜線：公式看起來就是公式。
  • 它本身不會自動做任何事。MarsDawn 不會幫你評分、摘要或標記這份文件——它只是把結構攤在你面前，讓你自己判斷。

接下來

  • 這樣的審閱怎麼不花 agent 自己的 context：節省 token 的審閱方式。
  • 把審閱過的文件交給別人：分享 PDF。
  • 為什麼難讀、該怎麼讀：讀懂 agent 交回來的 Markdown。
  • agent 為什麼要把計畫攤開：Anthropic 說 agent 要透明，那攤開的東西誰來讀？
