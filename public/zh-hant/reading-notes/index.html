編者的閱讀筆記

有六個人寫過 AI agent 是怎麼運作的：agent 是什麼組成的、什麼樣才算「agentic」、哪些設計模式真的撐得住、哪些還不成熟。他們都沒有寫過「怎麼讀 agent 交回來的東西」，也都沒有提到 MarsDawn 或推薦任何 Markdown 工具。我們照每篇文章自己的脈絡去讀，清楚標出我們自己的解讀從哪裡開始，然後對每個來源問同一個問題：因為這篇文章講的東西，最後會有什麼檔案落進你的資料夾？讀那份檔案的時候，MarsDawn 幫得上什麼忙？

想先看實用一點的版本，可以從〈讀懂 agent 交回來的 Markdown〉和〈五分鐘審完一份 agent 計畫〉開始。這六篇筆記比那兩頁更貼近原始文章；每一篇都能單獨讀，順序不拘。

  • 〈Anthropic 把 workflow 和 agent 分開來看，你的閱讀落在哪一邊？〉——Anthropic 寫給打造 agent 的人的指南，把固定的流程和自己決定下一步的模型分開來，還描述了一種「審查者」其實是另一次 LLM 呼叫、不是人的 workflow。
  • 〈Chip Huyen 的 read-only／write action 分類，核准前為什麼要看它〉——她對 agent 的簡單定義，以及「只是看」和「會改變東西」這兩種動作的差別，正好是五分鐘審閱最該花時間的地方。
  • 〈Lilian Weng 2023 年畫的 agent 藍圖，每個部件會留下什麼檔案〉——大腦、規劃、記憶、工具使用：她自己對 agent 組成的架構，以及她點名的一個限制：計畫遇到意外時不太會調整。
  • 〈Harrison Chase 的 agentic 光譜：愈自主，愈需要盯著看〉——他對 agent 的技術定義，以及他自己主張的：系統愈往光譜的自主那端走，就愈需要看得到系統內部。
  • 〈Jess Ou 的評測流程，裡面還留給你的那一步〉——2026 年 7 月，LangChain 在 Harrison Chase 2024 年那篇文章原本的網址上，發表了 Jess Ou 寫的新版〈What is an AI agent?〉；她的定義幾乎和他的一字不差，接下來也講清楚自動化評測到哪裡為止，剩下的還是要人來做。
  • 〈Andrew Ng 自己幫四種設計模式的可預測程度排序〉——在 The Batch 的五篇文章裡，他直接說出自己覺得哪些模式比較可靠、哪些難以預測。

這六篇文章都沒有主張「應該更仔細審閱 agent 的產出」，也都不是在談 MarsDawn。這個連結是我們自己畫的，每篇筆記都會這樣說清楚。
