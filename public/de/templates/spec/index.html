# Spezifikation: Name der Funktion

Status: Entwurf · Verantwortlich: Name · Aktualisiert: Datum

## Problem

_Was heute nicht stimmt, für wen, und woher wir das wissen._

## Ziele

- _Was gilt, wenn das ausgeliefert ist._

## Nicht-Ziele

- _Was das bewusst nicht tut._

## Anforderungen

| ID | Anforderung | Priorität |
|----|-------------|-----------|
| R1 | _Anforderung_ | Muss |
| R2 | _Anforderung_ | Soll |

## Ablauf

```mermaid
flowchart LR
  A[Start] --> B[Schritt] --> C[Ergebnis]
```

## Akzeptanzkriterien

- [ ] R1: _Wie wir es prüfen._
- [ ] R2: _Wie wir es prüfen._

## Offene Fragen

- _Frage._

So sieht sie aus

Exportiert mit marsdawn export spec.md. Das kostenlose Befehlszeilenwerkzeug rendert wie die Vorschau von MarsDawn, Diagramm inklusive.

Frag deinen Agenten

Schreib eine Spezifikation für [die Funktion] in spec.md und nutze dafür die Vorlage unter https://marsdawn.southern-light.dev/de/templates/spec/spec.md. Gib jeder Anforderung eine ID und verwende dieselben IDs im Ablauf und in den Akzeptanzkriterien. Wenn du fertig bist, führe marsdawn open spec.md aus.

Als PDF teilen

marsdawn export spec.md schreibt spec.pdf daneben, für alle, die kein Markdown lesen.

Was sie nicht kann

MarsDawn zeigt die Spezifikation, die Tabelle und das Diagramm. Es prüft nicht, ob die Akzeptanzkriterien jede Anforderung abdecken. Das ist die Aufgabe des Agenten, und deine beim Lesen.

Fragen

Muss für das Ablaufdiagramm etwas installiert sein?

Nein. MarsDawn und marsdawn export zeichnen Mermaid selbst, auch offline.

Kann ich die Spezifikation in MarsDawn bearbeiten?

Ja. Es ist ein Markdown-Editor mit der Vorschau neben dem Quelltext. Der Agent sieht deine Änderung, wenn er die Datei das nächste Mal liest.
